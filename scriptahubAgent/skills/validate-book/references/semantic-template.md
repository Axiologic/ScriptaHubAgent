# Existing translations and the English semantic template

English is corrected and validated first. Its explicit page containers define semantic content groups, not physical limits for translations. Each group may grow and span multiple displayed or printed pages. Text flows vertically; absolute source positions and fixed content heights are not copied into translations.

The single native implementation is `src/semantic-template.mjs`, used by both audit and correction. There is no environment switch, older template engine, positional style fallback, sentence rewriting or translation-generation stage.

1. Capture the accepted English page/container tree, computed presentation, fonts and ordered content slots. Tables retain row/cell spans. Text, images, lists, captions, notes and inline markup are inventoried.
2. Extract existing translated slots before removing old presentation. Preserve exact text, punctuation, target links, localized images and inline semantic markers. Capture CSS-only bold/italic differences before removing the old classes and declarations.
3. Shared identities delimit alignment intervals. Identities come from stable attributes and from language-independent numbering: `Chapter`/`Capitolul`, `Volume`/`Volumul`, `Part`/`Partea`, `Appendix`/`Anexa` and leading ordinals such as `1 . Title` and `1. Titlu` are normalised to the same anchor, so editions without shared IDs still align at their chapter boundaries.
4. Inside one interval, an order-preserving weighted alignment matches English slots to translated slots 1:1 where possible, keeps translated-only blocks in their document position, reports English-only units, and accepts a translated split or merge of consecutive blocks. Reused translated text is never rewritten, re-split or generated. A different sentence count, an extra translated block and a missing translated unit are reported as review findings; they do not block application while the rebuilt document preserves the complete ordered translation text.
5. Only these findings block a translation: a duplicated identity, reordered shared identities, a table grid or cell structure that differs from English, an interval too large for deterministic alignment, or a rebuild that would change the translated text, assets, links or semantic markers. The final candidate is rejected unless its complete ordered text and its image, link and marker inventory equal the existing translation.
6. Build a candidate from English containers and styles, filling slots with existing target nodes, then generate one managed stylesheet. Page and block heights remain automatic; English visual properties are retained and text may grow. English font resources are referenced relatively and are not copied. Unsupported fonts/assets remain validation errors. Because the English PDF subset faces lack target diacritics, serif roles reuse the bundled complete OFL face while a monospace source role (detected from the embedded font's native fixed-pitch/panose/name evidence) keeps a monospace stack, so the same source text type is not collapsed into a different face in translation. Source line breaks are stored as sentence indices in the English blueprint and re-inserted after the same sentence boundary of each translation, so every edition shares the source's logical line structure without copying English character widths.
7. Verify standalone and supported imported delivery at 1440, 1024 and 390 pixels, including real font rendering, overflow, overlap, clipping and resource loading. Candidate failures preserve the original document. Install only through the existing hash-bound recovery transaction and recheck the installed template.

Audit is read-only outside its job. Correction requires a complete association for the edition; a blocking finding leaves that edition unchanged while other editions continue. The report localizes the interval and retains both existing texts for targeted review. It never requests a full-book retranslation or claims that sentence counts prove meaning.

English presentation findings (justified spacing, font family or size, paragraph gaps, colour, display-page details) do not make its DOM skeleton unsafe as a translation blueprint and do not block applying the template. Structural English findings do: missing page containers, broken or misplaced anchors, unverified or fragmented tables, list-reconstruction failures, duplicate IDs and overlapping pages/blocks.

The English template needs explicit page containers. An unpaged source is reported; prepare/correct English pagination first. A sentence crossing a source page boundary is represented by its existing source fragments; this implementation does not infer semantic equivalence across languages or rewrite fragments.

Reapplying an unchanged template to unchanged content must produce identical HTML/CSS. Native tests cover preservation, CSS emphasis, continued semantic pages, table structure, cross-language numbered anchors, translated extras kept in place, regrouped sentence counts, ambiguous intervals and repeatability. This contract replaces independent translation pagination and mechanical sentence normalization.
