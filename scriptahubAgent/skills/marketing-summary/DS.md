# Design specification

## Purpose

Create a text-first sales page that gives readers a compelling reason to open a book without supplying the answers they would read it to discover. Input is semantic HTML, including HTML generated by `comprehensiveSummary`. Output remains in the source language and is a separate responsive HTML artifact.

## Pipeline

1. `prepare` snapshots the source, selects the visible summary article when the input is a comprehensive summary, otherwise extracts semantic book content, classifies non-content, and builds chapter-aligned batches near 32,000 characters.
2. The active LLM analyzes every batch into safe hooks and protected revelations. Safe hooks cover premise, questions, stakes, approach, atmosphere, starting conflict, and reader fit. Protected revelations cover answers, conclusions, solutions, prescriptions, twists, resolutions, and outcomes.
3. Cross-document synthesis detects fiction, nonfiction, or hybrid mode; selects only safe hooks; carries forward every protected revelation; and creates the sales-page outline.
4. The draft uses only selected safe hooks. A separate review compares every paragraph semantically against the complete protected ledger. Failed review returns the job to draft revision.
5. `build` validates schemas, evidence, guard phrases, review coverage, and adaptive length before atomically publishing a standalone page. `validate` independently inspects the published artifact.

## Adaptive budget

The interface intentionally has no length parameter. Up to 5,000 source words yields 250–300 output words; 5,001–20,000 yields 375–475; above 20,000 yields 550–650. Title, dek, headings, paragraphs, and closing text count. Hidden metadata does not. Sources too sparse to support the minimum without repetition or spoilers fail rather than being padded.

## Spoiler boundary

The boundary is genre-aware and conservative. Nonfiction copy may identify the problem, competing questions, stakes, and investigative method but not the work's answer or prescription. Fiction copy stops at setup and inciting conflict. Hybrid documents apply the stricter rule locally. Deterministic phrase guards supplement, but do not replace, the independent LLM review.

## Output and safety

The page contains a headline, dek, short sales-oriented sections, and a subtle open-loop ending. It contains no direct CTA button, price, rating, testimonial, invented reader benefit, or copied source scripts. Technical metrics, evidence IDs, and spoiler data stay in hidden metadata or the job report. The source is hash-checked and never modified.

## Node.js runtime

Requires Node.js 22 or newer. Use .mjs ECMAScript modules, explicit relative
imports, node: built-ins, async/await and node --test. Keep every owned resource
inside this skill. [dependencies.md](dependencies.md) records bundled parser and
language-data exceptions. Startup checks prerequisites and never installs them.

Run tests with Node.js:
`node --test tests/equivalence.test.mjs`. Frozen reference fixtures preserve
preparation, workflow states, exact HTML output and language normalization.
See tests/fixtures/README.md for provenance. Acceptance requires zero skipped tests.

Job JSON and command arguments are preserved. Doctor retains its behavioral
metadata and reports the Node.js and htmlparser2 versions.

Language tags use hyphenated BCP 47 syntax and are normalized by Node.js
`Intl.Locale`. The source language comes from HTML unless explicitly overridden.
