# Processing runtime dependencies

ScriptaHub uses Node.js 22 or later for the service and the built-in `node:sqlite` database. The agent image supplies the installed skill runtime at `/opt/scriptahub/runtime`. Its existing skill-specific `dependencies.md` files describe the conversion, browser, audio, model, and native dependencies and their bundled notices. Runtime preparation records the original source inventory before native installation; `verify-skills.mjs` checks the installed entry points and runs their doctors. The service preflight also starts a sandboxed doctor before a task is claimed.

The Linux worker additionally requires Bubblewrap with user, PID, IPC, network and mount namespaces, `--die-with-parent`, `--cap-drop`, `--size`, `--tmpfs` and `--remount-ro`; `/usr/bin/bwrap` is supplied by the agent image's Debian `bubblewrap` package. Bubblewrap is used because the hosted processor must not see the application data, credentials, callback socket or other tasks; a subprocess with an environment filter cannot provide that boundary. The exact installed package version and Debian license metadata are determined by the image build; they have not been verified in this checkout. Bubblewrap's upstream source and update instructions are at https://github.com/containers/bubblewrap. Its bundled license and notices must be retained with the image package. A missing or incompatible sandbox fails preflight; it is not installed at service startup.

On Linux, the service and its IPC clients require a writable `/dev/shm` for the private supervisor socket directory. This is the service's shared-memory mount, separate from the worker's isolated `/dev/shm`. Other platforms use `/tmp` for the socket directory.

The control-plane directory is owned by the service UID and has mode 0700. Processes with that UID are trusted, and the bound socket pathname is reserved until the listener closes. Node automatically unlinks that pathname on close; concurrent substitution by the same UID or root is unsupported. Before binding, the service rejects and preserves unexpected files, links and foreign sockets.

The fixed `deployment/processing-launch.py` uses the Python standard library and Linux `prctl` through `ctypes` to set a parent-death signal before entering Bubblewrap, and `resource.setrlimit` to apply a 512 MiB per-file limit. Python 3 is already required by the approved audio runtime and is supplied at `/usr/bin/python3` in the image. This narrow exception is needed because the Node.js standard library exposes neither Linux parent-death signals nor resource limits; a shell wrapper cannot close the parent-death race. No Python package or download is added. Python's license and bundled notices come from the image's Debian package; see https://www.python.org/downloads/ for upstream updates. Remove this launcher only when the supported runtime exposes equivalent parent-death and resource-limit primitives. A missing launcher or incompatible sandbox is reported by preflight before claiming work.

Input and terminal output inventories are limited to 4 GiB, 512 MiB per file, and 10,000 files. Disk-backed workspace use and free space are monitored during processing, with a 1 GiB free-space floor and a 4 GiB output allowance checked before launch. Monitoring can overshoot between checks and does not guarantee total memory usage or prevent exhaustion caused by other filesystem writers. Worker `/tmp` and `/dev/shm` are separate bounded tmpfs mounts of 1 GiB and 64 MiB. Processing retains terminal artifacts and charges their storage until the owning executor acknowledges the immutable result digest with `scriptahub_skill_job_release`. Cleanup intent is durable; artifact reads stop when cleanup begins, and storage reservations are released only after deletion and parent-directory synchronization succeed. Cleanup retries on replay, periodically and at startup. Stale uploads are cancelled after 24 hours without upload activity and follow the same cleanup-intent process.
